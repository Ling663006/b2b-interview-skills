# 访谈准备

## 目标与边界

围绕一个实际产品或业务判断，为一位受访者准备一场能执行的访谈。让主持人知道为什么问、如何跟进回答，以及现场记什么。

本文件可独立使用。用户提供模板时，内容和结构仍按本场研究需要调整。

本 skill 只负责访谈准备。多位受访者的招募与批次研究、访谈后的分析另行处理。录音、AI 转写、材料用途和保存确认由访谈组织方处理，不加入默认提纲。

## 1. 从已有信息确定访谈用途

先读取当前对话和相关材料，识别：访谈要支持什么取舍；受访者的角色与亲历范围；要研究的行为、事件、任务、概念或决策；已知事实与待验证假设；时间、方式及可查看的材料。

- 接受口头描述或已有产品资料、流程图、截图、制度、案例及历史研究。
- 只补问会实质改变方向、对象、场景、任务或时长的缺失信息，集中问清，不重复已有答案。能从目标判断访谈类型时，不要求用户选择分类。
- 不影响主线的缺口，用明确的低风险假设继续；会影响结论的公司实际做法，可列为现场核对问题。信息不足以确定核心用途时，先澄清用途。
- 用一句话写出本场要帮助团队作出的判断，再选出最重要的研究重点；数量由目标和时间决定，不固定题数。

## 2. 按需补足背景

分别判断“主持人是否需要理解背景”和“AI 是否缺少设计问题所需的信息”，不要把两者混为一谈。主持人的熟悉程度优先沿用其说明；仅在会改变准备方式时补问。

- **已有材料足够，主持人熟悉行业**：直接设计提纲，不生成行业综述。
- **已有材料足够，主持人不熟悉行业**：从材料解释必要的术语、角色、流程和判断依据；把解释放在相关问题旁或短背景说明中，不为解释背景重复检索。
- **缺少会改变问题设计的通用知识**：补充有针对性的检索，优先监管机构、行业协会、官方产品文档等一手来源。说明哪些是外部参考，并给出可核验的链接；时效影响理解时标注资料日期。
- **缺少公司内部事实**：向用户补问或写成现场验证问题。行业常见做法不能代替该企业的实际流程。

只保留能帮助主持人理解问题或识别差异的背景。把用户材料已说明的事实、外部通用参考和待核对内容区分开；不要把推测的角色、步骤、规则或原因写成已知事实。

## 3. 选择适合目标的访谈主线

围绕受访者能回答的内容安排主题。具体经历访谈选择亲历且相关的事件；可以是近期、典型或关键转折事件，不按预期结论筛选案例。混合研究时，先了解当前行为，再展示概念或原型。

- **探索**：从具体工作或经历理解目标、做法、工具、协作和边界。
- **问题验证**：还原问题如何发生、实际影响和当前处理方式；需要判断原因或流程差异时，增加相关对比或替代解释。
- **概念验证**：先了解现状，再看受访者如何理解概念、在什么场景有价值、采用需要什么条件。
- **原型测试**：以可执行任务为主线，观察实际理解、操作、错误和任务结果，不强套事件案例。
- **购买**：还原实际选择过程中的触发、评估、参与者、批准和切换条件。
- **流失**：还原预期、实际体验、补救、停用触发和后续替代。
- **满意度**：用具体经历解释体验、继续使用或推荐的原因。

只有差异会改变产品判断时，才增加正常与异常路径、其他案例、角色或材料核对。不要求每场都有完整流程、多个反例或购买链。涉及因果时，追问时间顺序、作用过程和其他可能原因；没有直接证据就保留未解问题，不用同时发生证明因果。

## 4. 写成主持人能使用的提纲

沿一条适合本场的主线组织开场、核心主题和收尾。流程探索在同一个核心主题中详细还原案例，步骤、交接、等待与收尾作为沿途追问；后续主题只补未覆盖且会改变判断的差异。建议时间直接标在各主题标题旁，合计等于本场时长；时长未知时给出可调整的建议。超时则缩小范围。

每个主题或任务写清：

- **目的**：这一段要理解什么。
- **起始问或任务指令**：能自然打开话题，或让受访者开始操作。
- **关键回答信号 → 追问方向**：只保留能补关键缺口或推进主线的追问，合并相近信号，写成“听到或看到什么 → 问、看或核对什么”；需要照读时给一句措辞。

问题落到具体业务对象、动作、判断依据和结果，按目的选择必要细节。受访者只讲概括评价时，引向具体经历；出现矛盾或因果判断时，核对过程和依据。问实际行为与条件，避免暗示答案或让受访者替团队设计功能。

开场用简短口语说明目的、范围及本场活动。收尾复述关键理解，让受访者纠正，并集中确认重要遗漏和后续核对事项。

## 5. 配上轻量记录区

记录区紧跟对应主题，用“事实或说法关键词”“原话、材料或时间位置（按需）”“待核实”三个普通段落留白，业务细节在栏内速记。用户明确需要记录表时再用表格，不为每个追问另设字段。

原型测试将事实栏换成“实际操作与任务结果”，需要判断独立完成时记录主持人的具体提示，区分独立与协助后完成；概念验证分开展示前现状和展示后反馈。流程研究在事实栏记录实际步骤、交接和材料，不预填未经确认的企业做法或受访者答案。

记录区用于速记，每项信息只留一个记录位置；收尾的更正和待核对事项也记在对应区内。只有明确的协作或追溯需求时，才补充编号和对应关系，现场无需分类证据或评分。

## 6. 交付与检查

默认交付一份 Word（.docx）访谈准备包，只包含简短用途与必要背景、带记录区的主持提纲。收尾及后续核对事项在提纲内记录，不另加访后清单或汇总表；背景无需补充时省略，边界提醒放在相关问题旁。

- 从空白文档直接创建 Word，使用内置标题层级、普通段落和记录留白，连续排版，不需要固定模板。使用环境可用且覆盖中文的字体；具备渲染能力时检查分页、裁切和缺字。
- 在对话中给出文件链接和简短说明。用户指定其他格式或只要对话正文时按其要求交付，不同时生成 Markdown、PDF 等副本；只有明确的分工或打印需求才拆分文件。无法生成或验证 Word 时如实说明，提供可用正文。
- 按用户要求减少可识别信息，避免纳入研究不需要的个人或商业敏感细节。

交付前内部核对：问题是否服务本场判断且受访者能回答；追问是否推进主线；未知事实是否被当成前提；提纲、记录区和时长是否一致；是否还有重复提问或记录区。该检查不输出为主持人自检章节。

不编造事实、原话或来源。受访者对其他角色的说法不等于对方已确认的事实；未找到支持、记不清或未覆盖是证据不足，只有支持相反判断的材料才是反证；一场访谈不能直接得出整个市场的结论。
