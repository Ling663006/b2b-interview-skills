# B 端产品用户访谈 Skills

两份可独立使用的中文 Agent Skills，帮助产品经理准备一场用户访谈，并把访谈材料整理成可回查、能支持产品判断的报告。

默认输出基础排版的 Word 文档，使用分层标题和普通段落，无需固定模板。用户也可以指定其他格式，或直接在对话中查看正文。

## 选哪个 skill

| Skill | 什么时候用 | 提供什么 | 默认得到什么 |
| --- | --- | --- | --- |
| [访谈准备](skills/interview-planning-kit/SKILL.md) | 访谈前，需要围绕实际产品或业务判断设计问题 | 研究目标、受访者角色、已有材料；行业熟悉程度和访谈时长按需补充 | 一份 Word 访谈准备包，含必要背景、主持提纲、回答信号对应的追问和轻量记录区 |
| [单次访谈报告](skills/interview-transcript-synthesis/SKILL.md) | 访谈后，需要理解本场发现及其依据 | 同一场访谈的转写、现场笔记和相关材料；研究目标或准备包可一并提供 | 一份匿名的 Word 轻量报告，含发现与研究回答、材料定位、未解问题与下一步核对事项 |

两份 skill 不互相依赖。可以只安装其中一份，报告也不要求先用准备 skill 生成提纲。

## 工作方式

准备从“这场访谈要帮助团队作出什么判断”开始。行业材料充足时直接设计问题；主持人不熟悉的内容按需解释。只有缺少会改变问题设计的通用知识时才补充检索，企业内部流程留待用户提供或现场核对。

访谈主线随目标调整，支持探索、问题验证、概念验证、原型测试、购买、流失和满意度访谈。探索现有流程时，沿一个具体案例连续追问，再补充会影响判断的差异，避免按清单反复问同一件事。

报告根据实际材料形成发现，区分亲历、观察、转述和推断，并保留时间戳、对话轮次、页码或段落等已有定位。准备包和行业背景用于说明目标，不会被当作访谈答案。

## 在 Codex 中安装

在支持 `$skill-installer` 的 Codex 环境中，可直接发送：

```text
使用 $skill-installer，从 https://github.com/Ling663006/b2b-interview-skills 安装
skills/interview-planning-kit 和 skills/interview-transcript-synthesis 这两个 skill。
```

也可以下载仓库，把需要的完整 skill 文件夹复制到个人目录 `~/.agents/skills/`，或项目内的 `.agents/skills/`。保持每个文件夹中的 `SKILL.md` 位于顶层。若安装后没有显示，重启 Codex。

文件结构、发现位置和调用方式参考 [OpenAI 官方 Skills 文档](https://learn.chatgpt.com/docs/build-skills)。其他支持 Agent Skills 的工具，请按其安装说明导入相应文件夹。

## 使用示例

以下均为虚构示例；实际使用时替换成自己的背景和材料。

### 访谈前：探索现有流程

```text
使用 $interview-planning-kit。

我们准备为一家设备服务商设计售后系统，希望先了解现有维修工单如何流转，
再判断最值得改善的环节。受访者是售后协调员，访谈 45 分钟。
我不熟悉设备售后业务。已有材料是当前工单表和一份处理流程说明，已附上。
请围绕一个实际维修案例设计访谈，生成带轻量记录区的 Word 准备包。
```

### 访谈后：整理一场报告

```text
使用 $interview-transcript-synthesis。

这是同一场售后协调员访谈的转写和现场笔记，已附上。
研究目标是了解维修工单的实际流转、关键判断和协作困难，支持售后系统的设计。
请生成匿名的 Word 轻量报告。根据实际材料回答研究问题，保留可回查依据，
将尚未确认的原因和需要核对的事项写清楚。
```

## 适用范围与运行条件

这两份 skill 都面向单次访谈，不负责招聘面试、问卷统计、批次招募或跨访谈综合。多场访谈需要另行比较，再判断某个发现是否具有更广泛的代表性。

本仓库只包含工作流程指令和可选的 Codex 界面描述，不包含 Word 模板或执行脚本。Word 创建与版式检查、联网检索、音频转写取决于所用工具的能力；无法执行时，skill 会说明限制并交付可用部分。访谈材料由使用者提供，发布仓库不包含真实受访者信息。
